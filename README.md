# App volume

Чистый LSPosed-модуль для панели громкости SystemUI в стиле crDroid: кнопка
громкости приложений и вертикальные ползунки активных плееров.

## Установка

1. Соберите APK: `bash build.sh`.
2. Установите `out/AppVolume.apk` как обычное приложение.
3. Включите модуль в LSPosed и выберите область `com.android.systemui`.
4. Перезагрузите устройство (или перезапустите SystemUI).

Больше ничего не нужно: модуль не требует Magisk/KernelSU, отдельного
companion-приложения, выдачи `android.permission.DUMP` и команд `settings put`.
LSPosed, разумеется, сам по себе требует root — это требование LSPosed, а не
этого модуля.

Если раньше был установлен flashable-модуль `appvolume`, удалите каталог
`/data/adb/modules/appvolume` и старый companion APK. Значения громкости,
сохранённые старым приложением, не переносятся: новый модуль хранит их в
настройках SystemUI.

## Совместимость

- AOSP 16.0: используется классический диалог `VolumeDialogImpl`; модуль
  добавляет кнопку в его нижний ряд и открывает прозрачную панель слева от
  него. Ползунки приложений нарисованы как вертикальные слайдеры Material 3
  Expressive из Android 16 QPR1/Android 17: трек 40dp, перемычка 52×4dp,
  иконка приложения 20dp.
- AOSP 16 QPR1 и Android 17: используется новая Compose-панель громкости,
  ползунки приложений встраиваются в неё.
- Оба варианта используют общий `SliderPanel`: одинаковый набор активных
  приложений, шаг 5%, порядок ползунков, выезд слева от основной панели и
  обратную анимацию сворачивания. Различаются только окно-хост и способ
  отрисовки ползунка.
- Панель приложений закрывается вместе с системной панелью громкости по её
  обычному таймеру автоскрытия. Модуль не удерживает системную панель на
  экране, пока открыта панель приложений.

## Как это работает

- SystemUI сам сканирует активные аудиоплееры (`dumpsys audio`), используя свои
  системные разрешения `DUMP` и `MODIFY_AUDIO_ROUTING`. Для каждого плеера
  находятся его piid, пакет и, если он есть, AudioFlinger session id.
- Кнопка панели следует за живыми событиями аудиосервиса
  (`AudioManager.registerAudioPlaybackCallback`): появляется сразу с первым
  звуком приложения и скрывается, как только все плееры остановлены. Скан
  `dumpsys` остаётся источником карты плееров и страховкой, если события
  недоступны. Снижение общей громкости до нуля кнопку не скрывает: важно
  состояние плеера, а не его слышимость.
- Основной путь изменения громкости — `AudioPlaybackConfiguration#getPlayerProxy()`
  и `PlayerProxy#setVolume()`. SystemUI получает неанонимизированные
  конфигурации и меняет множитель громкости в процессе самого приложения. Этот
  же множитель аудиосервис использует для приглушения плееров во время звонка,
  поэтому он работает и для обычных Java-плееров, и для быстрых/AAudio-потоков,
  к которым нельзя подключить сессионный эффект.
- Множитель периодически применяется заново, если приложение перезаписало
  громкость своего трека. Во время звонка (`AudioManager.getMode() != MODE_NORMAL`)
  запись не выполняется, чтобы не снять call mute; после возврата в обычный
  режим громкость применяется снова.
- `DynamicsProcessing` остаётся запасным путём для плеера без доступного proxy.
  Для сессий, которые уже покрыты proxy, эффект не создаётся, чтобы не
  приглушить звук дважды. К быстрым трекам сессионный эффект подключить нельзя.
- Значения громкости сохраняются в приватных настройках SystemUI и переживают
  перезапуск без внешнего сервиса.
